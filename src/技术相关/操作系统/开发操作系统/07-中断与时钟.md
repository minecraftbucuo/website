## 这一章要做成什么

到目前为止，内核的所有行为都是它**主动**发起的：开机、写字、画图，一路埋头干到底。可"操作系统"这个词的重心在"操作"——**管理**机器，而管理意味着**响应**：时钟每隔几毫秒叫它一声，好让它安排下一个任务；你一敲键盘它就得知道，好让它把字符接住。响应靠的不是内核勤快地到处张望，而是硬件主动来**叫醒**它——这就是中断。

本章结束时，你的系统第一次"活"起来，具体三件事：

1. **异常处理**：内核自己犯了错（比如除零、执行非法指令），不再无声复位，而是留下遗言再死——调试内核时这是救命的东西
2. **时钟心跳**：一个 100Hz 的定时器每秒叫醒内核 100 次——将来调度器的地基
3. **键盘回显**：你在 QEMU 窗口里打字，字符上屏——系统第一次对**输入**有反应

要动的东西：

- 新建 `kernel/src/gdt.rs`——GDT/TSS：中断系统的地基（提供段选择子和应急栈）
- 新建 `kernel/src/interrupts.rs`——IDT（中断号→处理函数的"电话簿"）、手写汇编存根、各路处理函数
- 新建 `kernel/src/pic.rs`——8259 中断控制器的调度 + PIT 定时器
- 新建 `kernel/src/keyboard.rs`——键盘驱动：扫描码翻译
- 修改 `kernel/src/serial.rs`、`console.rs`——全局化（处理函数里要打印，局部变量够不着）
- 修改 `kernel/src/main.rs`——按顺序接线

四个新模块的分工：

```
gdt.rs         地基：登记"代码段在哪、应急栈在哪"，IDT 表项要引用它
interrupts.rs  电话簿：中断号 → 存根（汇编，保存/恢复现场）→ 处理函数（Rust）
pic.rs         总机：外设的中断先经它中转，还有定时器
keyboard.rs    翻译官：键盘发来的位置码 → 字符
```

先讲清一件事的原理，再写它的代码，一路推进：地基（GDT）→ 电话簿（IDT）→ 总机（PIC）→ 定时器 → 键盘。

## 名词速查表

x86 是 40 年历史攒出来的机器，本章缩写格外多——它们全是后面章节的常用词，先过一遍，混个脸熟，后面正文随用随查：

| 缩写 | 全称 | 一句话 |
|---|---|---|
| GDT | Global Descriptor Table 全局描述符表 | 数组，每行一个"段描述符"；64 位下只管给段寄存器提供合法条目、挂 TSS |
| IDT | Interrupt Descriptor Table 中断描述符表 | 256 行数组：中断号 → 处理函数地址；敲键时 CPU 查的就是它 |
| TSS | Task State Segment 任务状态段 | 挂在 GDT 里的"应急信息卡"，关键内容是备用栈顶 |
| IST | Interrupt Stack Table | TSS 里那张 7 格的表（IST1~7），双重故障走 IST1 换干净栈 |
| CS | Code Segment 代码段寄存器 | "我正在哪个段里执行"；IDT 表项里存的 0x08 就是它该装的值 |
| 选择子 | segment selector | 段寄存器里存的数值 = GDT 行号 × 8 |
| IF | Interrupt Flag 中断标志 | rflags 里的一位，中断总开关；`sti` 置 1 开门，`cli` 清 0 |
| PIC | Programmable Interrupt Controller（8259） | 中断总机：15 路外设的线都接它 |
| PIT | Programmable Interval Timer（8253） | 定时器：恒定节拍，除数分频出目标频率 |
| IRQ | Interrupt ReQuest 中断请求线 | "总机的第几路线"——时钟 IRQ0，键盘 IRQ1 |
| ICW | Initialization Command Word | 重映射 PIC 时的初始化配置字节（ICW1~4） |
| IMR | Interrupt Mask Register | PIC 的免打扰名单：哪位写 1 哪路闭嘴 |
| EOI | End of Interrupt | 处理完中断给 PIC 的回执，不交线就哑 |
| ISR | Interrupt Service Routine | "处理函数"的学名；`IsrFrame` 的 ISR 就是它 |
| PS/2 | IBM Personal System/2 | 1987 年那台机器留下的键盘接口标准，代指老式键盘协议 |

外加两类特殊记法：

- Intel 手册里 **`#` 开头的都是异常**，本章用到 `#DE`（除零）、`#BP`（断点）、`#UD`（非法指令）、`#DF`（双重故障）
- **`int3` 是一条指令**（单字节机器码 `0xCC`），不是异常名——它的作用是"手动触发 3 号异常"。它就是调试器下断点的原理：把断点处指令的第一个字节偷换成 `0xCC`，程序跑到那就触发 #BP 落进调试器手里。我们用它自测中断链，因为它处理完正常返回、零副作用（对比：拿除零自测会死循环——异常返回的规矩是重执行出错指令本身，于是再除再触发）。`int N` 指令家族的其他成员（如 `int 0x80`）以后会用到

## 原理：中断到底发生了什么

假设你已经按下了键盘上的 A 键。从指尖到屏幕，完整走一遍：

```
你敲 A
  │
  ▼
键盘控制器把"第 30 号键按下"（一个字节 0x1E）放进自己的寄存器，
拉响一根专门的线（IRQ1），通知中断控制器 PIC
  │
  ▼
PIC（8259 芯片，外设中断的"总机"）查排班表：IRQ1 对应中断号 33，
通过另一根线通知 CPU
  │
  ▼
CPU 正在跑主循环，被叫停：把手头的活原封不动压进栈里
（返回地址、标志寄存器等，CPU 自动干），
然后查 IDT（中断描述符表，一张 256 行的电话簿）第 33 行，
拿到处理函数地址，跳过去执行
  │
  ▼
处理函数（我们用 Rust 写的）从端口 0x60 读出 0x1E，
查表翻译成 'a'，往屏幕盖章
  │
  ▼
处理函数给 PIC 交"回执"（EOI），然后执行 iretq 指令——
CPU 从栈里恢复被叫停时的状态，回到主循环刚才的地方继续睡
```

一次敲键，链条上每一环都有名有姓：**PIC 是总机（外设的中断不能都直接接 CPU，8259 芯片管着 15 路）；IDT 是电话簿（中断号查处理函数）；iretq 是"挂电话回去干活"。**

中断分两类，得分清：

- **CPU 异常**：CPU 执行指令时自己出的事——除零、非法指令、断点。同步的，你执行到那行代码它就响。编号 0~31，Intel 手册定死，不能改
- **硬件 IRQ**：外设主动叫门——时钟、键盘、磁盘。异步的，什么时候来完全看硬件心情。编号从 32 往后排

这里埋着一颗地雷：**PIC 出厂默认把 IRQ 0~15 排在中断号 8~23**——正好撞进 CPU 异常的保留区！IRQ0（时钟）会被当成 8 号（双重故障）处理，整个系统乱套。所以后面有一节专门的"重映射"，把 IRQ 挪到 32~47 这个安全区。

还有一个贯穿全章的铁律先立好：**处理函数必须把现场恢复得一丝不差**。被打断的代码完全不知道自己被中断过，你多弄脏一个寄存器、多弹一个栈，它醒来就是错乱。所以后面存根汇编里那些 push/pop 不是仪式，是保命。

## 原理：GDT——64 位下的"退役功臣"

要建 IDT，先得有 GDT。这话听着奇怪——GDT（全局描述符表）不是管"分段"的吗？32 位时代它确实大权在握（每段内存都要登记），但 64 位长模式下分段的活全被页表收走了。退役归退役，它没走，还管两件事：

1. **给段寄存器提供合法条目**。CS/DS/SS 这些段寄存器必须指向表里某个有效条目，否则一动就出错
2. **挂载 TSS**（任务状态段）——这才是本章真正要它的原因

**Limine 引导进 64 位时其实已经装过一份 GDT**（不然内核压根跑不起来），那为什么要自己再装一份？两个理由：一是别依赖别人的内部实现（Limine 的表长什么样哪天就变了）；二是我们要用 TSS，得往表里加自己的条目。

### 表长什么样

GDT 就是个 64 位整数的数组，每项 8 字节，下标叫**段选择子**（selector）。我们建 5 项：

```
下标   内容
0      空（规矩：第 0 项必须空）
1      代码段   ← 选择子 0x08
2      数据段   ← 选择子 0x10
3      TSS 低半 ← 选择子 0x18
4      TSS 高半
```

选择子 = 下标 × 8（低 3 位另有用途，我们全 0）。为什么 5 项里 TSS 占两项？TSS 是个 104 字节的结构，一条描述符的"基址+长度"字段在 64 位模式下装不下它的 64 位基址，所以系统段一律拆高低两半——记住了，下面填表用得上。

代码段描述符是一个 64 位数，关键位域拼出来是 `0x00209A0000000000`。不用背，会读就行：

```
0x9A = 1001 1010 (access 字节，从低到高)
        │ │ │ └─ A: 已访问（CPU 维护）
        │ │ └─── R: 可读（代码段的额外待遇）
        │ └───── C: 一致性位（特权级用，先 0）
        └─────── P=1 段在内存中；S=1 这是代码/数据段；
                type 位组合 1010 = "可读的代码段"
0x2 << 52 = L=1：64 位长模式（最重要的一个位，没它就不是我们这个时代了）
```

数据段 `0x0000920000000000` 同理，type 换成"可写的数据段"。64 位模式下基址和长度字段全部被无视（页表说了算），所以那堆 0 不是偷懒，是真没人看。

### TSS：CPU 的应急信息卡

TSS（任务状态段）在 32 位时代是个大权臣——它管"任务切换"，把整个进程的寄存器存这。64 位把这项权力废了，TSS 瘦身成一张信息卡，对内核有意义的只剩：

- **RSP0~2**：三个备用栈顶——将来进程从用户态陷进内核时换栈用（还没有用户态，先留空）
- **IST1~7**：七个**应急栈顶**。这有个真实的痛点：双重故障（异常处理中又出异常）发生时，当前栈很可能**已经坏了**（正是栈坏才引发的异常），在坏栈上处理双重故障 = 三重故障 = CPU 直接复位，连句话都不留。IST 的意义：**进门时先换一块干净栈**，让遗言能写出来

我们的用卡方案：IST1 挂一块 16KB 应急栈，专供双重故障。

### 最刁的一个坑：CS 换不了

装完表要"启用"：lgdt 装表，然后把各段寄存器指向新条目。DS/ES/FS/GS/SS 这些数据段寄存器好办，一句 `mov ds, ax` 搞定。**唯独 CS（代码段寄存器）没有 mov 指令**——它只在控制流转移时被 CPU 顺手换掉。 workaround 是一个漂亮的小把戏：

```
push 新CS选择子      ┐ 伪造一次"远返回"的栈布局
push 返回地址         ┘
retfq               ← 远返回：CPU 从栈里同时取 CS 和 RIP 换装
```

就是自己伪造一个"从远地方 call 过来"的现场，再借 `retfq`（远返回）让 CPU 以为在正常返回，顺手把 CS 换了。整个 64 位 OS 世界都这么干。

## 动手一：gdt.rs——立地基

开写 `kernel/src/gdt.rs`。逐段来。

第一段：常量与 TSS 结构——

```rust
//! GDT 与 TSS：64 位下的段描述符表和任务状态段。
//!
//! 64 位模式下"分段"已基本退役（地址翻译全权归页表），
//! GDT 只剩两件正事：给段寄存器提供合法选择子、挂载 TSS。

use core::arch::asm;
use core::mem::size_of;

/// 段选择子 = 表内行号 × 8（低 3 位是别的标志，我们全 0）。
/// 中断系统要用它填 IDT 表项，所以公开
pub const KERNEL_CODE_SELECTOR: u16 = 1 << 3; // 0x08

const KERNEL_DATA_SELECTOR: u16 = 2 << 3; // 0x10
const TSS_SELECTOR: u16 = 3 << 3; // 0x18

// access 字节 0x9A = 1001 1010：P=1（在内存中）/ S=1（代码或数据段）
//                                  / type=1010（代码、可读）
// 标志位 0x2 << 52 = L=1（64 位模式）
const KERNEL_CODE_DESC: u64 = 0x00209A0000000000;
// access 0x92 = 1001 0010：type=0010（数据、可写）
const KERNEL_DATA_DESC: u64 = 0x0000920000000000;

/// 任务状态段（TSS）：CPU 的"应急信息卡"。
/// 普通中断直接用当前栈；但灾难性故障发生时当前栈可能已坏，
/// CPU 会按 IST1~7 换到备用栈再进处理程序。
/// 所有字段由 CPU 直接读取——Rust 看不见这些读取，与 BOOT_STACK 同理
#[allow(dead_code)]
#[repr(C, align(16))]
pub struct Tss {
    resvd0: u32,     // 布局固定
    rsp: [u64; 3],   // RSP0~2：将来用户态切内核栈用（还没有用户态）
    resvd1: u64,     // 布局固定
    ist: [u64; 7],   // IST1~7：七个备用栈顶（接双重故障时启用）
    resvd2: u32,     // 布局固定
    resvd3: u16,     // 布局固定
    iomap_base: u16, // I/O 权限位图偏移：指向段尾 = "没有位图"
}
```

`Tss` 的字段顺序是 Intel 手册定死的内存布局，一个都不能挪——`#[repr(C)]` 关掉 Rust 的字段重排。`rsp`/`ist` 等字段只有 CPU 会去读，Rust 侧没有任何代码碰它们，编译器会误报"没人用"，所以 `#[allow(dead_code)]`——和 `BOOT_STACK` 当年一个待遇。

`set_ist`/`empty` 和 GDT 数组——

```rust
impl Tss {
    const fn empty() -> Self {
        Self {
            resvd0: 0,
            rsp: [0; 3],
            resvd1: 0,
            ist: [0; 7],
            resvd2: 0,
            resvd3: 0,
            iomap_base: size_of::<Tss>() as u16,
        }
    }

    /// 设第 n 号备用栈顶（n: 0~6，对应 IST1~7）
    fn set_ist(&mut self, n: usize, stack_top: u64) {
        self.ist[n] = stack_top;
    }
}

/// GDT 表：[null, 代码, 数据, TSS 低, TSS 高]
static mut GDT: [u64; 5] = [0, KERNEL_CODE_DESC, KERNEL_DATA_DESC, 0, 0];
static mut TSS: Tss = Tss::empty();

/// 双故障应急栈：进 #DF 处理函数时当前栈很可能已坏，换这块干净的。
/// 数组本体没人读（CPU 只用它的地址当栈），消除误报
#[repr(align(16))]
#[allow(dead_code)]
struct EmergencyStack([u8; 16 * 1024]);

static mut EMERGENCY_STACK: EmergencyStack = EmergencyStack([0; 16 * 1024]);
```

`iomap_base` 指向 TSS 段尾，意思是"不挂 I/O 权限位图"（那是用户态限权的工具，还早）。应急栈放 `.bss`，开机时 Limine 已把这片清零，直接可用。

`init()`——填表、装表、换段、挂 TSS，一口气：

```rust
/// GDTR：lgdt 指令读的"表在哪、多长"小卡片
#[repr(C, packed)]
struct Gdtr {
    limit: u16,
    base: u64,
}

/// 装载 GDT 和 TSS。kmain 里、开中断前调用一次
pub fn init() {
    unsafe {
        // IST1 = 应急栈顶（栈向低地址长，顶 = 数组末尾）
        let tss = &raw mut TSS;
        (*tss).set_ist(
            0,
            (&raw const EMERGENCY_STACK as *const EmergencyStack as u64)
                + size_of::<EmergencyStack>() as u64,
        );

        // TSS 描述符：基址 = TSS 的地址，段长 = TSS 大小 - 1。
        // access 0x89 = P=1 / S=0（系统段）/ type=1001（64 位 TSS）
        let base = (&raw const TSS) as u64;
        let limit = (size_of::<Tss>() - 1) as u64;
        let gdt = &raw mut GDT;
        // 裸指针要先解引用才能下标
        (*gdt)[3] = (limit & 0xFFFF)            // 段长低 16 位
            | ((base & 0xFFFFFF) << 16)     // 基址低 24 位
            | (0x89 << 40)                  // access 字节
            | (((limit >> 16) & 0xF) << 48); // 段长高 4 位
        (*gdt)[4] = base >> 32; // 基址高 32 位（64 位 TSS 特有）
```

先把应急栈顶写进 TSS 的 IST1（`&raw mut`/`&raw const` 是拿 static 地址的规范通道——edition 2024 起禁止对 `static mut` 取普通引用，raw 指针是唯一合法写法）。然后填 TSS 描述符——按 64 位系统段的字段布局把 limit、base、access 拼进 GDT[3]，基址高 32 位单独放 GDT[4]，正是上文说的"系统段拆两半"。

最精彩的一段，装表换段：

```rust
        let gdtr = Gdtr {
            limit: (size_of::<[u64; 5]>() - 1) as u16,
            base: gdt as u64,
        };

        asm!(
            "lgdt [rdi]", // 装表
            // 数据段寄存器直接 mov 装填
            "mov ds, ax",
            "mov es, ax",
            "mov fs, ax",
            "mov gs, ax",
            "mov ss, ax",
            // CS 不能 mov：压入新段 + 返回地址，远返回时换装。
            // 跳板用 r10——eax 全程装着数据段选择子，不能碰
            "push rsi",
            "lea r10, [rip + 2f]",
            "push r10",
            "retfq",
            "2:",
            "ltr dx", // TSS 装进任务寄存器
            in("rdi") &gdtr as *const Gdtr,
            in("eax") KERNEL_DATA_SELECTOR as u32,
            in("rsi") KERNEL_CODE_SELECTOR as u64,
            in("edx") TSS_SELECTOR as u32,
            out("r10") _,
        );
    }
}
```

前半好懂：`lgdt` 装表，五个数据段寄存器挨个 mov。`retfq` 三连就是原理一节讲的"伪造远返回"：压新 CS、压返回地址（`lea r10, [rip + 2f]` 取的是 `2:` 标签那行的地址，即换完段以后继续执行的位置），`retfq` 一执行 CS 和 RIP 同时换新。最后 `ltr` 把 TSS 挂上任务寄存器。

两个实战细节：① 标签名用 `2:` 不是 `1:`——新的 Rust 编译器禁止纯 0/1 的数字标签（会和二进制字面量混淆，详见踩坑实录坑 4）；② `out("r10") _` 是告诉编译器"r10 被汇编弄脏了"，同时声明输出免得它拿去干别的。

## 原理：IDT 与存根——电话簿和接线员

GDT 立好，现在建 IDT。它是一张 **256 行的电话簿**：中断号是行号，每行记着"处理函数地址 + 用哪个代码段（CS 选择子）+ 进门时用不用备用栈"。查表是 CPU 硬件自动干的——你敲键盘时 CPU 自己去翻第 33 行，翻完跳过去，全程不过内核任何代码。

每行 16 字节（64 位模式），叫一个**门描述符**（gate）。麻烦在于 64 位地址装不进一行：拆成三段存放——

```
低 8 字节：  目标地址低 16 位 | 段选择子 << 16 | IST | 类型字节 0x8E << 40 | 地址中间 16 位 << 48
高 8 字节：  地址高 32 位
```

类型字节 `0x8E` = P=1（有效）/ DPL=0（内核态）/ type=0xE（**中断门**）。中断门有个体贴的附带效果：进门时 CPU **自动清 IF 标志**（关中断）——处理函数跑着的时候不会又来一个中断打断，免得嵌套到栈爆。处理函数 iretq 出门时 IF 自动恢复。

### 存根：为什么是手写汇编

查表拿到地址后，CPU 跳过去执行的第一段代码，叫**存根**（stub）。它是一段"接线员"代码，职责只有一条：**把现场完整存进栈里，然后叫真正的 Rust 处理函数**。

写它为什么非得是裸汇编？因为 CPU 跳进来的时候：① 栈上是我们刚压的机器状态，没有合法的 Rust 栈帧；② 15 个通用寄存器全是被打断代码的值，编译器生成的任何函数序言都会破坏其中一些。另外还有个对齐坑：Rust 函数按 System V 约定要求进入时 rsp 按 16 字节对齐，而被打断代码的栈深浅完全随机——不对齐，编译器生成的 SSE 指令（比如 `movaps`）当场触发异常。

理论上 Rust 有个官方答案：`extern "x86-interrupt"` 函数，编译器自动生成全套存根。**但它是 nightly 专属**（本章作者亲测，stable 上编译报 E0658，见踩坑实录坑 1）——和 `limine` crate 当初的处境一模一样。于是自己写，用宏批量生成。

### 存根长什么样

以"保存 → 调用 → 恢复"为骨架，16 步：

```asm
push 0              ; ←（占位，见下文"错误码"）
push r15 ... push rax   ; 15 个通用寄存器逆序压栈
mov rbp, rsp        ; 记下帧位置（rbp 刚才已压栈，可以拿来做草稿）
and rsp, -16        ; 栈摆到 16 字节对齐
mov rdi, rbp        ; 第一个参数 = 帧指针（Rust 处理函数收到的 &mut IsrFrame）
call 处理函数
mov rsp, rbp        ; 回到帧
pop rax ... pop r15 ; 逆序恢复（push 的镜像）
add rsp, 8          ; 丢弃错误码（或占位）
iretq               ; 出门：CPU 自动恢复 rip/cs/rflags/rsp/ss
```

关于**错误码**：一部分异常（双重故障、缺页等）进门时 CPU 会在栈上多压一个错误码，其余异常和所有 IRQ 都没有。而存根的 push/pop 必须严格对称——`add rsp, 8` 那行要丢弃的要么是 CPU 压的真错误码、要么是我们自己压的 0。所以宏带一个参数：无错误码的传 `"push 0"` 占位，有的传 `"nop"` 顶替那一行。四个字的差别，错了就栈错位、iretq 回到火星去。

`iretq` 前不恢复 IF？不需要——iretq 自动恢复 rflags，IF 就在 rflags 里。中断门进门时清的，出门自动回来，一个字都不用我们管。

第一段：现场帧结构——栈上那些东西的 Rust 视角：

```rust
//! IDT：中断描述符表——"门铃编号 → 处理函数"的电话簿。
//!
//! 处理函数入口用手写汇编存根（stable 工具链没有 x86-interrupt
//! 调用约定，和当初的 limine crate 同一个处境）。

use crate::gdt::KERNEL_CODE_SELECTOR;
use crate::keyboard;
use crate::pic;
use crate::serial;
use core::arch::asm;
use core::arch::naked_asm;
use core::mem::size_of;
use core::sync::atomic::{AtomicU64, Ordering};

/// 中断现场的完整布局（字段从低地址到高地址，与存根压栈顺序一致）。
/// 寄存器字段是给调试输出留的，目前只读 rip——CPU 看不见这些，同 BOOT_STACK
#[allow(dead_code)]
#[repr(C)]
pub struct IsrFrame {
    // 通用寄存器（按压栈顺序）
    pub rax: u64, pub rcx: u64, pub rdx: u64, pub rbx: u64,
    pub rbp: u64, pub rsi: u64, pub rdi: u64,
    pub r8: u64, pub r9: u64, pub r10: u64, pub r11: u64,
    pub r12: u64, pub r13: u64, pub r14: u64, pub r15: u64,
    // 错误码（无错误码的异常由存根压 0 占位）
    pub error_code: u64,
    // 以下是 CPU 进入存根前自动压的
    pub rip: u64,
    pub cs: u64,
    pub rflags: u64,
    pub rsp: u64,
    pub ss: u64,
}
```

存根把 rdi 指向栈顶传给处理函数，而这个结构体的字段顺序和压栈顺序严格一致——于是在 Rust 里 `frame.rip` 就能读到出事地址。字段本身只有我们的代码读（CPU 不看），又是 dead_code 误报的常客。

第二段：存根生成宏——上一节那张骨架图直接翻译成 `macro_rules!`：

```rust
/// 生成一个中断存根。
/// $pre：无错误码的异常传 "push 0" 占位；有错误码的传 "nop"
///（CPU 已经压了真错误码，不能再压一份）
macro_rules! stub {
    ($name:ident, $handler:path, $pre:literal) => {
        #[unsafe(naked)]
        extern "C" fn $name() -> ! {
            naked_asm!(
                $pre,
                // 保存全部通用寄存器：被打断的代码不知道自己被中断过，
                // 一个都不能弄脏
                "push r15", "push r14", "push r13", "push r12",
                "push r11", "push r10", "push r9", "push r8",
                "push rdi", "push rsi", "push rbp", "push rbx",
                "push rdx", "push rcx", "push rax",
                // rbp 已保存在栈上，借来记帧位置并摆正栈：
                // Rust 函数要求进入时 rsp 按 16 对齐，而被打断的
                // 代码栈可没这个保证
                "mov rbp, rsp",
                "and rsp, -16",
                "mov rdi, rbp", // 第一个参数 = 帧指针
                "call {h}",
                "mov rsp, rbp", // 回到帧，开始恢复
                "pop rax", "pop rcx", "pop rdx", "pop rbx",
                "pop rbp", "pop rsi", "pop rdi",
                "pop r8", "pop r9", "pop r10", "pop r11",
                "pop r12", "pop r13", "pop r14", "pop r15",
                "add rsp, 8", // 丢弃错误码占位（或 CPU 压的真错误码）
                "iretq",
                h = sym $handler,
            );
        }
    };
}
```

`#[unsafe(naked)]` 声明"裸函数"——函数体里的汇编就是函数的全部，编译器一个字都不许加。压栈按 r15→rax 的固定顺序，恢复严格镜像（先进后出）。中间那五行是本章汇编最精华的部分：rbp 借来当帧锚点（它自己的值早已压进栈保底）、`and rsp, -16` 摆对齐、传参、调完 `mov rsp, rbp` 跳回锚点——对齐造成的间隙就这样被无损跳过。

第三段：处理函数们——存根身后的 Rust 世界：

```rust
// ---------- 异常处理函数（纯 Rust，从存根进入） ----------

/// 公用：汇报异常名和出事地址
fn report(name: &str, frame: &IsrFrame) {
    serial::print("\n[exception] ");
    serial::print(name);
    serial::print(" rip=");
    serial::print_hex(frame.rip);
    serial::print("\n");
}

extern "C" fn exc_divide_error(frame: &mut IsrFrame) {
    report("#DE 除零", frame);
}

extern "C" fn exc_breakpoint(frame: &mut IsrFrame) {
    report("#BP 断点", frame);
}

extern "C" fn exc_invalid_opcode(frame: &mut IsrFrame) {
    report("#UD 非法指令", frame);
}

/// 双重故障：异常处理过程中又出了异常。当前栈很可能已坏，
/// 所以它走 IST1 备用栈进门（见 IDT 登记处）。到这里没有"恢复"可言，
/// 打印遗言后停机——它的价值是把"无声复位"变成"留了句话"
extern "C" fn exc_double_fault(frame: &mut IsrFrame) -> ! {
    report("#DF 双重故障", frame);
    loop {
        unsafe { asm!("hlt") };
    }
}

/// 兜底：没登记处理逻辑的异常都到这。不返回——直接停机
extern "C" fn exc_unexpected(frame: &mut IsrFrame) -> ! {
    report("unexpected", frame);
    loop {
        unsafe { asm!("hlt") }; // 休眠等中断，比忙转省电
    }
}
```

`extern "C"`：和存根的 call 约定对上（第一个参数 rdi）。除零/断点/非法指令这三个处理完**正常返回**——被打断的代码接着跑（断点尤其如此，`int3` 本来就是"打个报告然后继续"）；双重故障和兜底异常则**绝不返回**：出这种事系统已不可救，`hlt` 循环停机等复位，好歹在串口留下了死因。

/// 滴答计数：系统的心跳秒表。
/// 原子变量——"读出来加一写回去"可能被下一次中断拦腰打断
static TICKS: AtomicU64 = AtomicU64::new(0);

        serial::print_hex(ticks / 100);

}

第五段：表项结构与登记处——

```rust
// ---------- IDT 表 ----------

/// IDT 表项（64 位模式一项 16 字节）
#[derive(Clone, Copy)]
struct Gate {
    low: u64,  // 低 8 字节
    high: u64, // 高 8 字节
}

impl Gate {
    const fn missing() -> Self {
        Gate { low: 0, high: 0 }
    }

    /// 登记处理函数。ist=0 用当前栈；1~7 用 TSS 第 n 个备用栈
    fn set_handler(&mut self, stub: usize, ist: u8) {
        let addr = stub as u64;
        self.low = (addr & 0xFFFF)                     // 函数地址 0..15 位
            | ((KERNEL_CODE_SELECTOR as u64) << 16)   // 用哪个代码段
            | (((ist & 0x7) as u64) << 32)            // 备用栈编号
            | (0x8E << 40)                             // 类型字节：中断门
            | (((addr >> 16) & 0xFFFF) << 48);         // 函数地址 16..31 位
        self.high = addr >> 32;                        // 函数地址 32..63 位
    }
}

static mut IDT: [Gate; 256] = [Gate::missing(); 256];
```

`set_handler` 就是按上文那张字段布局图逐段拼位。64 位地址被拆成低 16 / 中 16 / 高 32 三段藏进两个 u64——拆法是 Intel 定的，照抄即可。IST 字段填 1~7 就启用对应的备用栈。

最后建表装载，`init()`：

```rust
/// IDTR：lidt 读的"表在哪、多长"（和 GDTR 一个意思）
#[repr(C, packed)]
struct Idtr {
    limit: u16,
    base: u64,
}

/// 建表并装载。kmain 里、开中断前调用一次
pub fn init() {
    unsafe {
        let idt = &raw mut IDT;

        // 有正经处理逻辑的异常
        (*idt)[0].set_handler(stub_divide_error as *const () as usize, 0);
        (*idt)[3].set_handler(stub_breakpoint as *const () as usize, 0);
        (*idt)[6].set_handler(stub_invalid_opcode as *const () as usize, 0);
        // 双重故障：走 IST1 应急栈（登记里的 1 就是表项里的 IST 编号）
        (*idt)[8].set_handler(stub_double_fault as *const () as usize, 1);

        // 其余 CPU 异常（1~31 号中没专门登记的）全部兜底
        for i in 0..32 {
            if (*idt)[i].low == 0 {
                (*idt)[i].set_handler(stub_unexpected as *const () as usize, 0);
            }
        }

        // IRQ0（时钟）→ 中断号 32（PIC 重映射后的新门牌）
        (*idt)[32].set_handler(stub_timer as *const () as usize, 0);
        // IRQ1（键盘）→ 中断号 33
        (*idt)[33].set_handler(stub_keyboard as *const () as usize, 0);

        let idtr = Idtr {
            limit: (size_of::<[Gate; 256]>() - 1) as u16,
            base: idt as u64,
        };
        asm!("lidt [rdi]", in("rdi") &idtr as *const Idtr);
    }
}
```

注意两个写法：`stub_x as *const () as usize`——函数名不能直接转整数，要经裸指针中转（新版 Rust 的规矩）；`(*idt)[i]`——裸指针必须先解引用再下标（本章作者错了三次，见坑 2）。登记顺序：0/3/6 号是正经异常；8 号双重故障登记时 ist 填 1，对应 TSS 的 IST1 应急栈；0~31 里剩下的一律兜底；32/33 是重映射后的时钟和键盘。

## 原理：PIC——总机重排班

外设中断不是直接连 CPU 的，先过 8259 PIC（可编程中断控制器）这片 1981 年的老芯片。它管 15 路外设中断（IRQ0~15），像总机：外设的线接它，它排好优先级、决定放谁进来，再通知 CPU。

架构上是两片级联：主片管 IRQ0~7，从片管 IRQ8~15，从片的输出接在主片的 IRQ2 上——所以从片上的中断（IRQ8~15）要**两边都交回执**，这直接写进了后面的 EOI 代码。

**重映射**是绕不开的那颗雷：PIC 出厂把 IRQ0~7 排在中断号 8~15、IRQ8~15 排在 0x70~0x77，撞进 CPU 异常区。得告诉它换门牌：IRQ0~7 → 32~39，IRQ8~15 → 40~47。

和它说话靠四个端口（主片 0x20/0x21，从片 0xA0/0xA1），用的是一套问话流程（ICW，初始化命令字）：

```
ICW1（写命令口）0x11：开始初始化，"有级联，后面还有话"
ICW2（写数据口）新门牌起始号：主片 32，从片 40
ICW3 级联拓扑：主片说"从片挂我 2 号线"，从片说"我挂主片 2 号"
ICW4 0x01：8086 模式
最后写 IMR（中断掩码）：16 位里每 1 位挡一个 IRQ
```

**IMR（中断掩码寄存器）**是总机的"免打扰名单"：某位写 1，对应的 IRQ 就算响了也被压着。我们的策略：初始化完**先全挡住**——IDT 还没登记的 IRQ 放进来就是没登记的门铃，CPU 直接三重故障复位。之后谁登记了处理函数，谁再单独放行（`unmask`：读回当前掩码、清掉对应位、写回）。

**EOI（中断结束）**必须专门强调，它是 IRQ 处理的"回执"：处理函数干完活，要往 PIC 写一个 0x20 说"我办完了"。**不交回执，PIC 认为你还在办，这条线（以及优先级更低的所有线）永远静音**——时钟忘了交回执就只响一声然后永远哑掉。这是中断驱动里最经典的坑，症状还很迷惑（"只工作了一次"）。

## 原理：PIT——节拍器

时钟是哪来的？PIT（可编程间隔定时器，8253 芯片）一个出厂恒定 1193182 Hz 的节拍器，你可以设一个除数 N，它每 N 拍响一次。要 100Hz：N = 1193182 / 100 ≈ 11932。设法定死：往 0x43 端口写命令（通道 0、除数分两字节传、方波模式），再往 0x40 端口连写除数低、高字节。之后 IRQ0 每 10ms 响一次，风雨无阻。

## 动手三：pic.rs——总机调度

整个文件不长，一次看：

```rust
//! 8259 PIC（中断控制器）与 PIT（定时器）驱动。
//! 对应教程：docs/07-中断与时钟.md

use crate::serial::{inb, outb};

// 主/从 PIC 的端口（两片级联：主的 IRQ2 接着从片）
const MASTER_CMD: u16 = 0x20;
const MASTER_DATA: u16 = 0x21;
const SLAVE_CMD: u16 = 0xA0;
const SLAVE_DATA: u16 = 0xA1;

// 重映射的"新门牌"：IRQ0~7 → 32~39，IRQ8~15 → 40~47
const MASTER_OFFSET: u8 = 32;
const SLAVE_OFFSET: u8 = 40;

/// 重映射 PIC：把 IRQ 0..15 改接到中断号 32..47
pub fn remap() {
    // ICW1（写命令口）：开始初始化，告知"级联 + 后面还有 ICW4"
    outb(MASTER_CMD, 0x11);
    outb(SLAVE_CMD, 0x11);

    // ICW2（写数据口）：各自的新门牌起始号
    outb(MASTER_DATA, MASTER_OFFSET);
    outb(SLAVE_DATA, SLAVE_OFFSET);

    // ICW3：主从怎么级联——从 PIC 挂在主 PIC 的 2 号线上
    outb(MASTER_DATA, 0x04);
    outb(SLAVE_DATA, 0x02);

    // ICW4：8086 模式
    outb(MASTER_DATA, 0x01);
    outb(SLAVE_DATA, 0x01);

    // 掩码（IMR）：先全部挡住。IDT 还没登记的 IRQ 放进来
    // = 没登记的门铃 = 三重故障，所以谁要用谁显式 unmask
    outb(MASTER_DATA, 0xFF);
    outb(SLAVE_DATA, 0xFF);
}

/// 放行某个 IRQ（清掉掩码里的对应位）。
/// 掩码是"要挡谁"，先读回当前值再清位，不能凭空写死
pub fn unmask(irq: u8) {
    let port = if irq < 8 { MASTER_DATA } else { SLAVE_DATA };
    let mask = inb(port);
    outb(port, mask & !(1 << (irq % 8)));
}

/// 中断处理完的回执（EOI）。不回执，总机会一直压着后续的中断
pub fn send_eoi(irq: u8) {
    // 从 PIC 的中断要两边都交（从片 → 主片），主片的交自己就够
    if irq >= 8 {
        outb(SLAVE_CMD, 0x20);
    }
    outb(MASTER_CMD, 0x20);
}

/// 启动 PIT：每秒敲 hz 次铃
pub fn init_timer(hz: u32) {
    const BASE_HZ: u32 = 1193182; // PIT 的出厂节拍
    let divisor = BASE_HZ / hz;
    outb(0x43, 0x36); // 通道 0、除数两字节（先低后高）、方波模式
    outb(0x40, (divisor & 0xFF) as u8);
    outb(0x40, (divisor >> 8) as u8);
}
```

四个函数对着原理一节逐条看即可。`unmask` 里值得多看一眼的细节：IMR 上 1 = 挡，所以放行是**清位**（`& !(1 << n)`）；而且必须先 `inb` 读回当前掩码再改——时钟和键盘各放行各的位，直接写死一个值就把别人放行的撞没了。

## 动手四：全局化——处理函数也要说话

到这里中断系统主体齐了，但有个悬而未决的问题：**处理函数里要打印**（异常日志上串口、按键上屏幕），而 `SerialPort` 和 `Console` 现在都是 kmain 的局部变量——处理函数隔着函数边界，够不着。

解法和 boot.rs 里的"请求单"、和任何内核的日志系统一样：**全局单例**。Rust 的 static 要求类型实现 Sync（多线程安全），而 `SerialPort`/`Console` 内部有裸指针，编译器不敢自动担保——需要我们亲手担保：

```rust
/// 共享包装：UnsafeCell + 手写 Sync（单核、且从不并发写，安全）
struct Shared<T>(UnsafeCell<T>);
unsafe impl<T> Sync for Shared<T> {}

impl<T> Shared<T> {
    const fn new(value: T) -> Self {
        Self(UnsafeCell::new(value))
    }
    fn get(&self) -> &mut T {
        unsafe { &mut *self.0.get() }
    }
}
```

`unsafe impl Sync` 是一句承诺："我保证不会有两条执行流同时碰它"。承诺的依据：单核；中断门进门自动关中断（IF 清零），处理函数执行期间不会有第二个执行流插进来。等将来上了多核，这里得换成带锁的真货——但在那之前，这 8 行就是最轻的全局单例。

串口那边，`serial.rs` 末尾补上（上一章教程里 `let mut com1 = ...` 的局部变量写法到此退役）：

```rust
/// 全局 COM1：内核任何代码（包括中断处理函数）都能借它说话
static COM1: Shared<SerialPort> = Shared::new(SerialPort::new(SerialPort::COM1));

/// 开机初始化（kmain 里调用一次，替代原来的局部变量写法）
pub fn init() {
    COM1.get().init();
}

/// 打印字符串——内核版 print!
pub fn print(s: &str) {
    COM1.get().send_str(s);
}

/// 按 16 进制打印 u64（no_std 没有 format!，自己排）
pub fn print_hex(value: u64) {
    const HEX: &[u8; 16] = b"0123456789ABCDEF";
    let mut buf = [b'0'; 16];
    let mut v = value;
    for i in (0..16).rev() {
        buf[i] = HEX[(v & 0xF) as usize];
        v >>= 4;
    }
    // 去掉前导零（全零时保留一个 '0'）
    let start = buf.iter().position(|&b| b != b'0').unwrap_or(15);
    COM1.get().send_bytes(&buf[start..]);
}
```

`print_hex` 顺手实现了（no_std 里没有 `format!`，打印地址只能自己排）：16 位十六进制逐位查表，再掐掉前导零。

屏幕那边，`console.rs` 末尾照方抓药——唯一的差别是**屏幕可能压根不存在**（真机没给 framebuffer），所以包一层 `Option`，没屏幕时 print 静默丢弃，内核也不至于崩：

```rust
// ---------- 全局化（模式同 serial.rs 的 Shared） ----------
// 键盘处理函数要把字符印上屏，Console 不能再是 kmain 的局部变量

/// 共享包装：UnsafeCell + 手写 Sync（单核、且从不并发写，安全）
struct Shared<T>(UnsafeCell<T>);
unsafe impl<T> Sync for Shared<T> {}
impl<T> Shared<T> {
    const fn new(value: T) -> Self {
        Self(UnsafeCell::new(value))
    }
    fn get(&self) -> &mut T {
        unsafe { &mut *self.0.get() }
    }
}

/// 全局控制台。屏幕拿到之前是 None——那时 print 静默丢弃
///（真机没给 framebuffer 的场合，内核也不至于崩）
static CONSOLE: Shared<Option<Console>> = Shared::new(None);

/// 拿到屏幕后调用（kmain）：建控制台并清屏
pub fn init(fb: &Framebuffer) {
    let mut con = Console::new(fb);
    con.clear();
    *CONSOLE.get() = Some(con);
}

/// 打印到屏幕（全局入口，谁都能调）
pub fn print(s: &str) {
    if let Some(con) = CONSOLE.get().as_mut() {
        con.write_str(s);
    }
}
```

键盘还要一个新技能：**退格**。顺手给 `Console` 加上（`put_byte` 的 match 里加一行，方法放 `newline` 旁边）：

```rust
    /// 处理一个字节：'\n' 换行，退格，可打印字符盖章右移，其余忽略
    pub fn put_byte(&mut self, b: u8) {
        match b {
            b'\n' => self.newline(),
            b'\x08' => self.backspace(),
            0x20..=0x7E => {
                self.draw_char(self.col, self.row, b);
                self.col += 1;
                if self.col >= self.cols {
                    self.newline(); // 行满自动换行
                }
            }
            _ => {} // 其他控制字符（\t、\r 等）暂不支持
        }
    }

    /// 退格：光标退一格，把那格涂回背景色
    fn backspace(&mut self) {
        if self.col > 0 {
            self.col -= 1;
            self.draw_char(self.col, self.row, b' ');
        }
    }
```

退格的"擦"就是"拿空格盖章"——上一章"格子永远整个涂满"的设计在这里回收了红利：擦除不需要新机制。

## 原理：键盘——它发的不是字符

最后一件事：键盘。它比想象的原始得多。

**键盘不发字符，发"位置码"。** 按下 A 键，键盘发来的不是 `'a'`（0x61），而是 `0x1E`——含义是"主键区第三排第一个键被按下"。这种码叫**扫描码**（scancode）。我们用第一套（scan code set 1，IBM PC AT 传下来的标准）。"按下 A 出什么字符"完全是内核翻译的结果——所以不同国家的键盘布局在内核里就是不同的翻译表。

三个必须处理的细节：

- **按/松各报一次**：敲一下 A，来两个码——按下 `0x1E`，松开 `0x9E`（最高位置 1 = 松开）。松开码直接丢弃
- **Shift 自己记**：大小写不是键盘的事。得维护一个"Shift 按着吗"的状态：Shift 按下记 true、松开记 false，翻译时按状态选普通表还是 Shift 表
- **扩展前缀**：方向键、右 Ctrl 这类后来加的键，会先发一个 `0xE0` 再发本码。暂时用不上它们，但**必须认出并吞掉** `0xE0` 和它后面跟的码——不然方向键会被错翻成别的字符

数据从端口 0x60 读（键盘控制器的数据口，`inb` 终于登场）。IRQ1 经重映射后是 33 号门铃。

## 动手五：keyboard.rs——翻译官

```rust
//! PS/2 键盘驱动：读扫描码，翻译成字符上屏。
//! 对应教程：docs/07-中断与时钟.md

use crate::console;
use crate::serial::inb;
use core::sync::atomic::{AtomicBool, Ordering};

/// 扫描码集 1 的 ASCII 对照表：下标 = 扫描码，值 = 字符（0 = 无对应字符）。
/// 按行对应键盘物理排布，对照着看很直观
static NORMAL: [u8; 59] = [
    0, 0x1B, b'1', b'2', b'3', b'4', b'5', b'6', b'7', b'8', b'9', b'0', b'-', b'=',
    b'\x08', b'\t', b'q', b'w', b'e', b'r', b't', b'y', b'u', b'i', b'o', b'p', b'[', b']',
    b'\n', 0, b'a', b's', b'd', b'f', b'g', b'h', b'j', b'k', b'l', b';', b'\'',
    b'`', 0, b'\\', b'z', b'x', b'c', b'v', b'b', b'n', b'm', b',', b'.', b'/',
    0, b'*', 0, b' ', 0,
];
/// Shift 按下时的对照表（同行位置，大小写和符号切换）
static SHIFTED: [u8; 59] = [
    0, 0x1B, b'!', b'@', b'#', b'$', b'%', b'^', b'&', b'*', b'(', b')', b'_', b'+',
    b'\x08', b'\t', b'Q', b'W', b'E', b'R', b'T', b'Y', b'U', b'I', b'O', b'P', b'{', b'}',
    b'\n', 0, b'A', b'S', b'D', b'F', b'G', b'H', b'J', b'K', b'L', b':', b'"',
    b'~', 0, b'|', b'Z', b'X', b'C', b'V', b'B', b'N', b'M', b'<', b'>', b'?',
    0, b'*', 0, b' ', 0,
];

/// Shift 按着吗（两边的 Shift 键共用一个状态就够了）
static SHIFT: AtomicBool = AtomicBool::new(false);
/// 上一码是扩展前缀 0xE0 吗（方向键等会先发一个 0xE0）
static EXTENDED: AtomicBool = AtomicBool::new(false);
```

两张表下标就是扫描码，读的时候按物理排布一行行对过去：`0x02` 是 `1` 键……`0x1E` 是 a，`0x1C` 是回车。0 = 无对应字符（Ctrl、Alt、CapsLock 这些）。表长 59 = 覆盖到 `0x3A`（CapsLock）为止——多出的键反正也是 0。

处理函数本体：

```rust
/// 键盘中断到来：从 0x60 端口取一个扫描码，翻译上屏
pub fn on_interrupt() {
    let sc = inb(0x60); // 键盘控制器的数据口

    // 扩展码：0xE0 后面跟的码（方向键/小键盘区）先忽略
    if EXTENDED.swap(false, Ordering::Relaxed) {
        return;
    }
    if sc == 0xE0 {
        EXTENDED.store(true, Ordering::Relaxed);
        return;
    }

    let released = sc & 0x80 != 0; // 最高位 = 松开
    let code = sc & 0x7F;
    match code {
        0x2A | 0x36 => SHIFT.store(!released, Ordering::Relaxed), // 左/右 Shift
        _ if released => {} // 其他键的松开码直接忽略
        _ => {
            let table = if SHIFT.load(Ordering::Relaxed) {
                &SHIFTED
            } else {
                &NORMAL
            };
            if let Some(&ch) = table.get(code as usize).filter(|&&c| c != 0) {
                // 单字节 ASCII 一定是合法 UTF-8，from_utf8 不会失败
                let buf = [ch];
                if let Ok(s) = core::str::from_utf8(&buf) {
                    console::print(s); // '\n'、退格、可打印字符都由 put_byte 处理
                }
            }
        }
    }
}
```

逐段看：开头两道闸管扩展码——`swap` 一箭双雕（读旧值 + 复位），`0xE0` 本身登记"下一个码是扩展码"。然后按位拆出"松开"标志和本码。三个分支：Shift 按下/松开只改状态不上屏；其他松开码丢弃；按下码查表翻译。翻译结果一个字节，得包成 `&str` 才能进 `console::print`——单字节 ASCII 永远是合法 UTF-8，`from_utf8` 必成功，包着写只是类型过关。`\n`、`\x08`、可打印字符由此各归各位，全靠 put_byte 那张 match。

## 动手六：main.rs——按顺序接线

所有零件就位，最后是装配。顺序本身就是知识点——**每一步都有它必须在那个位置的理由**：

```rust
mod boot;
mod console;
mod font;
mod gdt;
mod interrupts;
mod keyboard;
mod pic;
mod serial;
```

kmain 主体（帧缓冲 match 的两端）：

```rust
/// Rust 世界的入口。先让串口说话，再向 Limine 领屏幕。
#[unsafe(no_mangle)]
pub extern "C" fn kmain() -> ! {
    // 串口全局化：从这以后任何代码（包括中断处理函数）都能 serial::print
    serial::init();
    serial::print("\n=== MOS booting ===\n");

    // 换上自己的 GDT/TSS（中断系统的地基，必须在开中断之前）
    gdt::init();
    serial::print("gdt loaded\n");

    // 立起 IDT 电话簿，然后自测：手动按响 3 号门铃（断点）。
    // 处理函数打印完会"若无其事"地回来——中断系统的第一次往返
    interrupts::init();
    serial::print("idt loaded, ringing int3...\n");
    unsafe { core::arch::asm!("int3") };
    serial::print("returned from int3, interrupts work\n");

    // 外设中断三件套：重映射 PIC → 放行时钟和键盘 → 开中断
    pic::remap();
    pic::unmask(0); // IRQ0：时钟
    pic::unmask(1); // IRQ1：键盘
    pic::init_timer(100);
    unsafe { core::arch::asm!("sti") };
    serial::print("interrupts enabled, clock ticking\n");

    match FRAMEBUFFER_REQUEST.response() {
        Some(resp) if !resp.framebuffers().is_empty() => {
            let fb = resp.framebuffers()[0];
            serial::print("framebuffer acquired\n");

            // 控制台全局化：键盘处理函数里也能上屏了
            console::init(fb);
            console::print("=== MOS booting ===\n");
            console::print("hello, screen!\n\n");
            console::print("keyboard ready - type something!\n\n");

            serial::print("console up\n");
        }
        _ => {
            serial::print("no framebuffer!\n");
        }
    }

    // 主循环升级：hlt = 躺下等门铃。每次滴答醒来处理完，接着睡——
    // 这就是操作系统主循环的雏形（以后会进化成调度器）
    loop {
        unsafe { core::arch::asm!("hlt") };
    }
}
```

装配顺序里三处点睛：

- **`int3` 自测**：`sti` 之前先手动触发一次断点异常——存根、处理函数、iretq 整条链当场跑一遍。断点处理完正常返回，主循环若无其事继续——"打断→处理→恢复"的完整往返，比任何单元测试都直接
- **`sti` 前排干所有准备**：GDT→IDT→PIC 重映射→放行→定时器，最后才 `sti`（置 IF 标志，开中断）。顺序反了任何一步，都是"门铃接了但电话簿还没印好"的灾难
- **主循环从忙等换 `hlt`**：hlt 让 CPU 睡到下一个中断。以前 `spin_loop` 是醒着空转烧电，现在是真睡——有活干时被叫醒，干完接着睡。这个循环就是将来调度器的胚子

另一处顺手的变化：上一章那 60 行 `the quick brown fox...` 滚屏验证退役了——屏幕要留给你的键盘输入，打几个字就滚走没法看。滚屏本身上一章已经验收。

**然后是本章的高光时刻**：点一下 QEMU 窗口（把键盘焦点给它），随便打字——**你打的每个字直接上屏**。顺手验证几个细节：

- Shift + 字母出大写、Shift + 数字出符号（那张 SHIFTED 表在工作）
- 回车换行、Backspace 真能往回擦（不是光标动一下）
- 方向键、CapsLock 没反应——故意忽略的
- 你打字的同时串口的 `[timer]` 心跳照常跳——两路中断互不干扰，各走各的门铃

**没有按预期？按症状对号**：

- `[timer]` 只出现一次就哑了 → EOI 没交或没交对（检查 `send_eoi(0)`）
- 敲键没反应，但 `#BP` 和 timer 都正常 → IRQ1 没放行（`unmask(1)`）或 33 号没登记
- 一敲键就复位重启 → 大概率扫描码表越界或存根 push/pop 不对称
- 开机直接三重故障复位 → IDT 没装（lidt 没执行）就 sti 了

退 QEMU 还是老规矩：`Ctrl+A` 松开再按 `X`。

## 踩坑实录

**坑 1：`extern "x86-interrupt"` 是 nightly 专属（E0658）。**

本章最初想走官方近路：处理函数标上 `extern "x86-interrupt"`，编译器自动生成存根、自动保存恢复现场，全套优雅。一编译：

```
error[E0658]: ABI is experimental and subject to change
  --> src/interrupts.rs:xx:xx
   = note: see issue #... for more information
```

stable 工具链用不了，和第一章的 `limine` crate 同款处境。解法也同款：自己写。手写宏存根多花四十行，但换来的是把"保存现场→对齐→调用→恢复→iretq"每一行都过一遍手——对学 OS 反而是好事。**教训：教程世界里号称优雅的 nightly 特性，stable 项目用前先查门禁。**

**坑 2：裸指针不能直接下标（`cannot index into *mut [T; N]`）。**

本章错得最密集的一处，同一个坑连着踩三次。`static mut IDT` 取地址得到 `*mut [Gate; 256]`，直接写 `idt[3]` 编译器拒绝：裸指针没实现 Index。正确写法是先解引用再下标：`(*idt)[3]`。道理明白还是手滑——大概因为 Rust 里"解引用"大多数时候是隐式的，唯独裸指针这里必须显式。规律：**写 `static mut` 的访问代码时，看见裸指针就条件反射补括号星号**。

**坑 3：内联汇编的寄存器撞车（`register rax conflicts with eax`）。**

gdt 装载的 asm! 块里，跳板想拿 rax 当草稿算地址，但同一个块已经声明了 `in("eax")` 装数据段选择子——eax 就是 rax 的低半，一个寄存器两种身份，编译器直接报冲突。换一个没人用的（r10）了事。写内联汇编时寄存器分配心里得有张表：声明过 in/out 的（哪怕只用了半截），块内就全是它的。

**坑 4：汇编标签不能用纯 0 和 1（`avoid using labels containing only the digits 0 and 1`）。**

存根和跳板里的局部标签随手写了 `1:`/`1f`，新版 rustc 给出这个劝告性报错：纯 0/1 组成的标签会和二进制字面量产生解析歧义（LLVM 层面的问题）。全部改成 `2:`/`2f`。规矩记下：**asm 里的数字局部标签从 2 起编**。

**坑 5：OVMF 固件在串口上"抢话筒"。**

验证 gdt loaded 时，串口输出里时不时插着几行乱码/半截 OVMF 日志——那是 QEMU 的固件自己在用同一条串口（它也拿 COM1 当日志口），和内核输出交错。无害，看日志时心里把它滤掉即可；要清爽可以用 QEMU 的 `-serial` 多路配置分离，暂时不值当。

## 本章小结

- 中断 = 硬件叫醒内核：外设→PIC（总机）→CPU 查 IDT（电话簿）→存根→处理函数→EOI→iretq 回到被打断处，一条链每环有名有姓
- 两类中断要分清：CPU 异常（0~31，同步）和硬件 IRQ（32+，异步）；PIC 默认门牌撞异常区，必须重映射到 32~47
- 64 位下 GDT 退役但管两件事：合法段条目 + 挂 TSS；CS 不能 mov，靠"伪造远返回 + retfq"换装；TSS 的 IST 给双重故障备了块干净应急栈
- 存根手写汇编四步曲：保存现场（15 寄存器）→ rbp 锚点摆 16 字节对齐 → call Rust 处理函数 → 镜像恢复 + iretq；错误码占位（push 0 vs nop）必须和异常类型对上
- EOI 是 IRQ 的回执，忘交总线就哑；IMR 先全挡、谁登记谁 unmask
- 键盘发的是扫描码不是字符：查表翻译、Shift 状态自己记、0xE0 扩展码要吞掉
- 处理函数要打印 → serial/console 全局化：`Shared(UnsafeCell)` + 手写 Sync，担保依据是"单核 + 中断门自动关中断"
- 主循环换成 `hlt`：睡等中断，有活才醒——这是将来调度器的胚子

**里程碑**：内核活了——时钟每 10ms 叫它一次，你一敲键它就接住，自己犯错还能留遗言 ✅
