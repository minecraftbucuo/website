# 07 附录 · 前传：这些老东西是怎么长成这样的

> 配合 [07-中断与时钟](07-中断与时钟.md) 阅读。正文给名词下了定义（"GDT 是一张表"），
> 但没解释**为什么非要这张表**。如果你读完定义还是懵——正常，这些机制是 40 年里
> 一个问题摞一个问题长出来的，跳过中间的问题直接看答案，谁都会懵。
> 这篇补上中间的过程：从"什么都没有"开始，每个问题逼出一个解法，
> 解法又留下新的问题，最后长成正文里你看到的那个样子。

## 开场：先把 CPU 想象成一个什么样的机器

把一切历史、术语都忘掉，CPU 只干一件事：

```
从内存里取出一条指令 → 执行 → 取下一条 → 执行 → …
```

它有两个天生的特点，后面所有故事都从这两个特点长出来：

**第一，它没有眼睛耳朵。** CPU 本体只认识内存和它自己身上的几十个口袋（寄存器）。键盘、时钟、硬盘——它统统不知道存在。那它们的数据怎么进来？只能 CPU 主动去某个编号的窗口（IO 端口）拿。问题立刻出现：**CPU 怎么知道什么时候该去拿？** 键盘的键不是定时按的。

**第二，它没有表。** CPU 自己不知道时间。主循环跑得快，全靠外界告诉它"过了一秒了"。同样的问题：**谁来告诉它？**

这两个问题的最笨解法一模一样：**轮询**——CPU 死循环里不停地问每个设备"有事吗？有事吗？有事吗？"。能跑，但 CPU 的全部人生变成了查岗，正经活一点干不了。80 年代的真实困境就是：机器越做越快、设备越来越多，查岗查不起了。

要打破轮询，得让设备能**主动喊** CPU。于是有了"中断"这个概念——本篇的主角。

---

## 第一幕：先拉一根铃铛线（中断的诞生）

最原始的中断，物理上就是一根电线：所有设备共享一根线，谁有事就把这根线的电压一拉——CPU 的电路设计成"看到这根线被拉了，就暂停当前指令流"。

能喊了，但只知道"有事"，不知道**是谁**、**该干什么**。

解法：喊的时候报个数。设备拉线的同时，往一个约定的地方放一个编号（中断号），CPU 被打断后先读编号，再按编号决定干什么。

这个设计到今天没变过，只把"约定的地方"和"按编号决定干什么"制度化成了正文里的名词：

- 编号 → **中断号**
- "按编号决定干什么"的对照表 → **IDT**（正文里那张 256 行的电话簿）

为什么是"查内存里的一张表"而不是把处理逻辑焊死在 CPU 里？想想就知道：键盘的处理代码是我们自己写的 Rust 函数，CPU 出厂的时候它还不存在——**处理逻辑只可能放在内存里，CPU 只可能去查表**。表放内存、内容随便填，这叫可编程。

## 第二幕：线不够用了（PIC 的诞生）

一根线，很快不够用：时钟要喊、键盘要喊、磁盘也要喊，大家挤一根线，CPU 分不清是谁。

物理上的解法很直接：**多拉几根**。x86 CPU 实际上有两根中断线（一根可屏蔽、一根不可屏蔽），但设备有十几个——差了一个数量级，全靠 CPU 自己长引脚不现实。

于是 1981 年，IBM PC 的主板上放了一颗独立的芯片干这活：所有设备把线接到**它**身上（15 路，每路一个编号，就是 **IRQ**），它负责汇总、排优先级，然后去拉 CPU 那一根线，同时把对应的编号递过去。这颗芯片就是 8259，**PIC**。

一句话总结它存在的原因：**CPU 的引脚是稀缺资源，所以中断也要有个"总机"。** 它是主板上一个真实的、独立于 CPU 的芯片——今天你在 QEMU 里跟它说话，QEMU 在模拟 1981 年那颗真芯片的每一个寄存器。这就是为什么它叫"可编程"中断控制器：它的分号规则（IRQ 编号对应哪个中断号）不是焊死的，开机时由软件写进去——这个"写规则"的动作就是正文里的**重映射**。

顺带把同主板上另一颗芯片也认了：8253（**PIT**，定时器）。它跟中断系统是配合关系：它的唯一工作是**按设定好的频率**拉 IRQ0 这根线。上一幕说 CPU 没有表——现在有表了，就是它。同样，QEMU 里它在模拟一颗 1981 年的真芯片，"1193182 Hz"是它的晶振频率，出厂就这样。

到这幕结束，硬件侧的全家福凑齐了：

```
设备们 ──各拉一根 IRQ 线──► 8259 PIC ──汇总成一根线──► CPU
                                ▲
              8253 PIT 定时器 ──┘（专职拉 IRQ0）
```

## 第三幕：被打断的人不能察觉（现场的诞生）

现在 CPU 会在任意两条指令之间被拉走。这带来一个极严厉的约束：

**被打断的程序，醒来时必须和睡着前一模一样。**

为什么这么苛刻？因为它没法配合——它甚至不知道自己被打断过。它睡之前刚算出 `rax = 42`，醒来 `rax` 变成了别的值，程序逻辑直接错乱，而且这种错**无法复现、无法调试**（中断什么时候来是随机的）。所以规矩定成"绝对无感"，一点讨价还价的余地都没有。

"一模一样"具体指什么？CPU 执行一条指令的**全部状态**：

- 十几个通用寄存器（口袋里的值）
- 下一条指令的地址（被打断时它正要取的下一条）
- 标志寄存器（上一条指令算出的进位/溢出等标志）
- 栈的位置（它自己的工作现场在栈上）

谁来存？分工是自然形成的：

**CPU 自动存**它独知、软件够不着的部分：下一条指令的地址、标志、栈位置——这三样在执行 `iretq`（中断版"返回"）时也会被 CPU 自动恢复，软件想插手都插不了。

**软件必须存**通用寄存器——因为 CPU 一进处理函数就要开始用它们（哪怕只是为了执行"把数据从端口搬进来"这种最简单的活），**它自己弄脏的东西它没法负责保管**。所以处理函数的入口处得先把所有口袋的值抄到栈上，出口处再抄回来。

这就是正文里那段手写汇编存根的全部意义——你现在知道了，那 16 步 push/pop 不是什么高深法术，就是"把口袋挨个抄下来、办完事挨个抄回去"的纪律而已。存根（stub）这个词也是这么来的：它不是干活的人，它只是接电话的"接线员"，把电话转给真正的处理函数。

## 第四幕：编号打架（重映射的来历）

PIC 是 1981 年的产品，它的默认分号规则是：IRQ0~7 对应中断号 **8~15**。当年这个安排毫无问题——8086 那个时代的 CPU 里，0~15 这些编号是空的，随便用。

坏事的是后来。1982 年之后的 80286、80386 引入了**异常**（exception）体系：CPU 执行指令出问题（除零、非法指令、缺页……）时，也走中断那套"报个号、查表、跳处理"的机制，号固定占 **0~31**。从此中断号这块地皮被划走了一半，而 8~15 正好在被划走的范围里。

这时 PC 已经卖出去几百万台，软件、主板、操作系统全都默认"IRQ 就是 8~15"——改不动了，成了遗产。

于是留给每一个自制操作系统的人一道绕不开的手续：**开机时告诉 PIC "重新分号，从 32 开始"**。这就是重映射，正文里那四组 ICW 配置字节干的就是这件事。现在你能理解为什么"必须做"了——不做，时钟的中断（IRQ0 → 8 号）会被 CPU 当成"双重故障"（8 号异常）处理，整个系统一开机就精神错乱。

## 第五幕：段的户口本（GDT 的来历）

GDT 的故事要单独讲，因为它和历史的关系最绕。

**1978 年，8086 时代。** 寄存器 16 位，一个寄存器能表示的地址只有 64K，但当时市场想要 1MB 内存。解法：拿两个寄存器拼一个地址——一个"段地址"左移 4 位，加上一个"偏移"，凑出 20 位的实际地址。注意这时候的"段"**纯粹是算术把戏**，没有任何检查：任何程序都能用任何段地址访问任何内存。

**1982 年，80286，保护模式。** 多任务时代来了：好几个程序同住一台机器，"任何程序访问任何内存"等于灾难——你的程序手一抖就抹掉了别人。解法：给段**上户口**。段寄存器不再直接存段地址，改存一个**索引**（这就是"选择子"），CPU 拿索引去查一张**全局户口表**——表里每行写明"这个段从哪开始、多长、什么权限（只读？可执行？）"。这张表就是 **GDT**。从这一刻起，"越界访问别人的内存"从正常操作变成了 CPU 主动拒绝的违规。

**1985 年，80386，32 位 + 分页。** 段之外又发明了分页（把内存切成固定大小的页、按页翻译地址）——**分页比分段好用得多**（粒度细、支持换出磁盘）。从此新系统都用页，段只作为兼容遗产陪跑。

**2003 年，x86-64。** 干脆立法：64 位模式下，段的"基址+长度"字段**全部忽略**，地址翻译全权归页表。分段正式退休。

那 GDT 为什么还在？两个残留的正式用途（正文详述过）：① 段寄存器还得指向表里某个合法条目——硬件规矩没删干净；② 表里除了"代码段/数据段"这类户口，还允许挂**别的系统结构**（下一幕的主角 TSS 就挂在 GDT 里）。于是 64 位的 GDT 从"全国户口数据库"缩编成"两三个条目的小告示牌"——我们那张 5 行的表，就是这么来的。

顺带一个历史彩蛋，正文说"CS 不能用 mov 换"——为什么设计成这样？因为 80286 引入保护模式时，**换段=换权限**，是敏感操作，必须走控制流转移（跳转/返回）让 CPU 有机会做权限检查。mov 只搬数值、不做检查，所以设计者干脆不给段寄存器留 mov 通道。我们用"伪造远返回 + retfq"绕的，就是这条 1982 年立下的规矩。

## 第六幕：一个失败的野心（TSS 的来历）

TSS 的名字叫"任务状态段"（Task State Segment），这名字是它失败的证据。

80386 时代，Intel 的设计者有个大梦想：**让 CPU 硬件直接管理多任务**。设想中，操作系统只要说一声"切换到任务 B"，CPU 就自动把任务 A 的全部寄存器存进一个结构、把任务 B 的全部寄存器装回来——这个存任务的结构就是 TSS，"任务切换"这个动词 T 就是它的本名。

现实是：硬件任务切换太慢（要一条条搬运几十个寄存器），灵活度又差（操作系统的调度策略花样百出，硬件写死的流程跟不上）。所有主流操作系统（Linux、Windows）都**没用它**，全改成软件自己保存/恢复寄存器。野心失败，TSS 从"任务切换中枢"降级成了遗留结构。

但降级时留了两样有用的东西，正好是我们今天要的：

- **RSP0**：从低权限代码进高权限代码时，CPU **必须**换一个栈（权限低和高的代码不能共用一个栈，否则低权限代码可以窥探/破坏高权限栈）。切换到哪个栈？查 TSS。这是 TSS 在 64 位下的头号正式用途——等我们做用户态（第 10 章）时它会真正上岗
- **IST**（七格备用栈表）：处理"进门时栈已经坏了"的灾难场面（双重故障）——正文里 16KB 应急栈挂的地方

所以我们对 TSS 的用法是历史的"废物利用"：一个被时代抛弃的任务切换机构，我们只摘走它那张记着备用栈位置的小卡片。

## 第七幕：总机的两条规矩（EOI 与 IMR 的来历）

最后补上 PIC 使用手册里的两条规矩，它们的来历同样直接：

**EOI（回执）。** PIC 拉响 CPU 的线之后，默认**保持沉默**直到收到"办完了"的回执——这是中断优先级机制的代价：PIC 得记住"谁还在被服务中"，期间不送同级别和更低级别的中断进来（不然低优先级中断能被高频时钟无限打断，饿死别人）。所以"办完交回执"是软件的义务，忘交就是那根线永远哑掉。

**IMR（免打扰名单）。** 15 路线不会同时都接好处理函数——表里没登记的门铃响了，CPU 查表查到空行，直接触发三重故障整机复位。所以规矩是：开机默认全部静音，谁的处理函数写好了、登记了，再把对应位打开（unmask）。出事的窗口被这条规矩堵死。

## 收场：现在回头看那张图

把七幕的成果摞起来，正是正文开头那张链路图——现在每个箭头你都认识它了，因为你知道它是被哪个问题逼出来的：

```
你敲键
  → 键盘放好编号，拉 IRQ1        （第一幕：让设备能喊）
  → 8259 总机汇总，报中断号 33    （第二幕：线不够，加总机；第四幕：重排过号）
  → CPU 暂停，自动存关键现场       （第三幕：被打断者不能察觉）
  → 查 IDT 第 33 行，跳进存根      （第一幕：可编程查表）
  → 存根抄下所有寄存器，叫处理函数   （第三幕）
  → 处理函数读端口、翻译、上屏      （正文的世界）
  → 交 EOI 回执                    （第七幕）
  → 存根恢复寄存器，iretq 回去      （第三幕）
```

以及图外的两条暗线：GDT/TSS 是分段时代的遗产（第五、六幕），IDT 表项里引用着它们；PIT 是那颗专职摇铃的定时器（第二幕）。

再回到正文，你会发现自己读的不是一堆黑话，而是一台你知道全部来历的机器。

## 这篇的读法建议

不用背。建议读两遍：第一遍现在读，混个"每个东西都有来历"的直觉；然后去读正文，卡住的时候回来查对应的那一幕。第二遍是读完正文之后——那时再看"8086 拼地址""80286 上户口""80386 的野心"，会有"原来那行代码对应的是这段历史"的爽感。

真正的操作系统学习，一半是写代码，另一半就是逐步消化这台机器的历史包袱——你今天撞上的每一个"为什么要这么绕"，背后都有一段 40 年前的商业或工程决策。读懂它们，你就和当年那批工程师想到了一起。
