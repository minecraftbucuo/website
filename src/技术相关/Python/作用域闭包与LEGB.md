# 作用域、闭包与 LEGB（2026.10.8）

Python 按 **LEGB** 顺序查找名字：Local（局部）→ Enclosing（外层函数）→ Global（模块）→ Builtins（内置）。

闭包会保存外层作用域中的变量：

```python
from collections.abc import Callable

def make_multiplier(scale: float) -> Callable[[float], float]:
    def multiply(x: float) -> float:
        return x * scale
    return multiply

double = make_multiplier(2.0)
print(double(3.0))  # 6.0
```

循环中创建闭包时要注意**延迟绑定**：闭包在调用时才读取外层名字。

```python
bad = [lambda: i for i in range(3)]
# 三个 lambda 都不接收参数，调用时才去读外层变量 i
# 此时循环早已结束，i 停留在最后的值 2
# 所以三个调用结果全是 2，而不是预想的 0、1、2
print([fn() for fn in bad])   # [2, 2, 2]

good = [lambda i=i: i for i in range(3)]
# i=i 是默认参数：每轮定义时把当时的 i 值固定进这个 lambda
# 三个 lambda 各自保存了 0、1、2，调用时读自己的 i
print([fn() for fn in good])  # [0, 1, 2]
```

先从语法上把 `bad` 这一行拆开：

```python
bad = [lambda: i for i in range(3)]
```

- `lambda: i` 是一个 **lambda 函数（匿名函数）**，等价于 `def 临时名(): return i`。冒号前面是参数列表——这里是空的，所以它**不接收任何参数**；冒号后面的 `i` 是它的返回值。
- `for i in range(3)` 是**列表推导**，会循环 3 次。每轮循环都执行一次 `lambda: i`，**创建一个全新的匿名函数对象**。所以循环结束后，`bad` 是一个装着 **3 个无参 lambda 函数**的列表——注意列表里存的是函数本身，不是调用结果。
- 后面用 `fn()` 加括号才是真正**调用**这些函数。

这里最容易看漏的一点：推导的循环变量是 `i`，lambda 体内引用的也是 `i`，两者是**同一个变量**——lambda 并没有自己的 `i`，它只是引用了外层推导作用域里的那个 `i`。这正是“闭包”：函数把外层作用域的名字捕获了进来。

**为什么 `bad` 里的三个函数结果都是 2？**

关键在于闭包保存的是“名字”而不是“值”。列表推导每轮创建的 lambda 都引用同一个变量 `i`，而 `i` 在循环结束后最终是 `2`。等真正调用 `fn()` 时才去读 `i`——那时循环早已结束，读到的自然是最后的 `2`。也就是说：

- **定义时**：只记下“我要读外层的 `i`”，不记录 `i` 当时的值；
- **调用时**：才真正去读 `i`，读到的是它的最终值。

三个 lambda 读的是同一个 `i`，所以结果全是 2。

**为什么循环结束后 `i` 还在？**

如果你写过 C 或 Java，可能会觉得循环结束后循环变量就该销毁了。Python 不是这样：

- **Python 的作用域只看函数和模块，不看代码块。** `if`、`for`、`while` 都不创建新作用域，循环变量 `i` 直接定义在它所在函数（或模块）的作用域里。循环只是反复给同一个 `i` 赋值，结束后 `i` 依然存在，值是最后一次赋的 `2`。这也解释了为什么循环外随手读 `i` 在 Python 里是合法的。

- **列表推导是唯一的例外，但结论不变。** Python 3 中推导式有自己独立的作用域（这是为了防止 `i` 泄漏污染外部），循环结束后你看不到外面的 `i` 了——但三个 lambda 通过闭包**引用着推导内部的那个 `i`**。只要有函数还引用它，这个作用域就不会被销毁，`i` 的最终值 `2` 一直可读。

所以无论哪种情况，调用时读到的都是“活着的 `i` 的最终值”。

**为什么 `good` 用默认参数就对了？**

默认参数在**函数定义时**求值（这正是上一篇默认参数陷阱的相反用法）。`lambda i=i: i` 在每一轮循环中都把当时的 `i` 值固定成了自己的局部默认值——三个 lambda 各存一份 `0`、`1`、`2`，调用时读的是自己的 `i`，不再去看外层那个变来变去的 `i`。

如果需要在内层函数中重新绑定外层函数的名字，使用 `nonlocal`；重新绑定模块全局名字则使用 `global`。优先通过参数和返回值传递状态，通常更易测试。
