# 名字、对象与引用（2026.10.8）

Python 变量更准确的说法是**名字绑定到对象**。赋值通常不会复制对象，只会建立新的引用：

```python
a = [1, 2]
b = a
b.append(3)

print(a)        # [1, 2, 3]
print(a is b)   # True：指向同一个对象
print(a == b)   # True：值相等
```

需要区分两个运算：

- `is` 比较对象身份，适合写 `x is None`；
- `==` 调用值比较逻辑，比较“内容是否相等”。

函数参数同样是名字绑定。函数收到的是对象引用，不是“按引用传递”或“按值传递”这两个传统标签中的任意一个：

```python
def mutate(xs: list[int]) -> None:
    xs.append(1)          # 修改调用方可见的同一个列表

def rebind(xs: list[int]) -> None:
    xs = [1, 2]           # 只让局部名字 xs 指向新列表

data: list[int] = []
mutate(data)
print(data)               # [1]

rebind(data)
print(data)               # 仍然是 [1]
```

**为什么 `rebind` 之后 `data` 仍然是 `[1]`？**

关键在于区分“修改对象”和“重新绑定名字”这两件事：

- `mutate` 里的 `xs.append(1)` 是**修改对象**：`xs` 和外面的 `data` 指向同一个列表，对这个列表的改动双方都看得见。
- `rebind` 里的 `xs = [1, 2]` 是**重新绑定名字**：它没有碰原来的列表，只是让局部名字 `xs` 改指向一个新建的列表。函数调用时 `xs` 是 `data` 的一个引用副本——副本本身被改了，但 `data` 依然指回旧列表。

用图来看：

```text
mutate 时:   data ──┐
                    ├──> [1]        # 同一个对象被修改，双方可见
             xs ────┘

rebind 时:   data ─────> [1]        # 原对象没动
             xs ─────> [1, 2]       # 局部名字指向新对象，函数返回后即被回收
```

所以 `print(data)` 输出的仍然是 `[1]`。如果想让函数的改动对外可见，要么像 `mutate` 那样就地修改对象，要么用 `return` 把新对象带出来再赋值回去。

这套模型能解释大量常见 Bug：默认可变参数、浅拷贝、缓存污染以及多线程共享状态。
