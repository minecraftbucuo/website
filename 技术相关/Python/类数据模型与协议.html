类、数据模型与协议（2026.10.9）

Python 的特殊方法（前后各两个下划线的方法，也叫“魔法方法”）让对象接入语言协议。“协议”在这里的意思是：Python 内置的语法和函数背后，会去调用对象身上约定好的方法。比如你实现了 __len__，len(obj) 就能工作；实现了 __iter__，对象就能被 for 遍历。语法是表面，特殊方法才是真正的实现入口。

from dataclasses import dataclass
from collections.abc import Iterator

@dataclass
class Batch:
    samples: list[list[float]]

    def __len__(self) -> int:
        return len(self.samples)

    def __iter__(self) -> Iterator[list[float]]:
        return iter(self.samples)

batch = Batch(samples=[[1.0, 2.0], [3.0, 4.0]])
print(len(batch))   # 2

for sample in batch:
    print(sample)

这段代码值得逐行看：

  • @dataclass 是 Python 自带的一个装饰器，会自动帮我们生成 __init__（还有 __repr__、__eq__ 等）样板代码，所以这里我们只声明了字段 samples，就能写 Batch(samples=...) 来构造，不用手写构造函数；
  • len(batch) 能算出 2，是因为定义了 __len__——len() 这个内置函数实际上会转调 batch.__len__()；
  • for sample in batch 能遍历，是因为定义了 __iter__——for 循环每次迭代都会向对象要迭代器。也就是说，我们没有写任何遍历的代码，只是接入了“可迭代”这个协议。

这就是数据模型的设计思想：与其记住一堆“某某类型的对象支持某某操作”，不如把操作统一成“对象实现了哪个特殊方法”。自定义类、内置的 list、甚至 PyTorch 的 DataLoader 都遵循同一套约定。

常见特殊方法及用途

方法触发方式典型用途
__init__创建实例后初始化实例状态
__repr__repr(obj)、调试器无歧义的调试表示
__call__obj(...)让实例表现得像函数
__enter__ / __exit__with管理资源生命周期
__iter__ / __next__for、next定义迭代协议
__getitem__obj[key]索引、切片或映射访问

两点说明：

  • __repr__ 和 __str__ 很容易混淆。调试器、日志、交互式解释器显示对象时用的是 __repr__，它的目标是无歧义——最好能看出对象里到底装了什么；__str__ 面向最终用户的展示，可以更友好。只定义 __repr__ 时，str(obj) 也会退而用它，所以日常多数类只写 __repr__ 就够了。
  • __call__ 让实例可以像函数一样被调用，nn.Module 就是靠它做到 model(x) 等价于 model.__call__(x)——调用入口之外还能统一挂前置/后置逻辑（钩子、日志），这是框架里非常常见的模式。

实例方法、类方法和静态方法

先补一个地基：“方法”到底是什么？

方法就是定义在类里、能读改写该类对象内部状态的函数。一个类里装两类东西：一类是"数据"，叫属性（比如前面 Batch 里的字段 samples，你通过 batch.samples 去取）；另一类是"操作这些数据的函数"，叫方法（比如你要对它做点什么操作）。调用方法有一套固定写法：对象名.方法名(...)。

实例方法是最普通、最常见的一种方法。它的特别之处在于：Python 会自动把一个"指向正在调用这个方法的那个对象"的参数塞给它，程序员习惯把这个参数命名为 self。换句话说，你写 batch.method(...) 的时候，Python 实际把它变成 Batch.method(batch, ...) 来执行——前面那个 batch 自动填进了 self。

所以 self 不是需要你手动传的参数，它是"当前是哪个对象在调用"的替身。方法靠它才能读写"那个对象"自己的字段，而不是操作别处不相干的东西。这是理解后面所有内容的关键，先记住这句：self = 调用者对象本身。

现在再回来看三类方法，差别就一句话——第一个参数绑定到了谁：

  • 实例方法：第一个参数是 self，绑定到"调用它的那个实例"，操作具体对象；
  • @classmethod：第一个参数是 cls，绑定到"类本身"，常用于备选构造器；
  • @staticmethod：不绑定任何对象，仅用于把相关工具函数组织在类命名空间中。

三种方法的差别就在“第一个参数绑定到了谁”：

  • 实例方法绑定实例：self 指向调用它的那个对象，读写实例状态。必须先有实例才能调：device.kind；
  • 类方法绑定类：cls 指向类本身，而不是某个实例。所以它不需要先有实例，直接用类名就能调：Device.parse("cuda:0")；
  • 静态方法谁也不绑定：它放进类里纯粹是为了归类，去掉 @staticmethod 写成模块级函数也一样。

“备选构造器”是什么意思？

构造一个 Device，正常方式是 Device(kind="cuda", index=0)——但这要求你手里已经拆好了两个参数。现实中数据往往是别的形式，比如一个字符串 "cuda:0"，直接传给 Device() 会报错，因为 Device 不认识字符串。

所谓“备选构造器”，就是除了 __init__ 之外的另一种造实例的路子：把“拆字符串”这些准备工作写在一个类方法里，让它最后替你调用 Device(...)：

@dataclass
class Device:
    kind: str
    index: int

    @classmethod
    def parse(cls, value: str) -> "Device":
        kind, index = value.split(":")
        return cls(kind=kind, index=int(index))

device = Device.parse("cuda:0")   # 等价于 Device(kind="cuda", index=0)

对照着看 parse 里的三行：先把 "cuda:0" 按冒号拆开，再把 "0" 转成整数，最后 cls(kind=kind, index=int(index)) 这一句才是真正的构造——和 Device(kind="cuda", index=0) 一模一样。所以 parse 没有替代 __init__，只是包装了它：调用方从此可以直接 Device.parse("cuda:0")，不用自己拆字符串。

为什么用 cls(...) 而不是直接写 Device(...)？因为 cls 指向“通过哪个类调用的 parse”。如果有个子类 NpuDevice(Device)，调用 NpuDevice.parse("npu:1") 时 cls 就是 NpuDevice，构造出来的是子类实例；硬编码 Device(...) 的话，子类的 parse 也会造出父类对象。这就是类方法相对硬编码类名的隐蔽优势。
