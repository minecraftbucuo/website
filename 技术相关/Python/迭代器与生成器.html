迭代器与生成器（2026.10.15）

可迭代对象能返回迭代器，迭代器保存遍历状态，并通过 __next__ 逐个返回元素。生成器函数是编写迭代器的简洁方式：

from collections.abc import Iterator

def read_batches(path: str, batch_size: int) -> Iterator[list[str]]:
    batch: list[str] = []
    with open(path, encoding="utf-8") as file:
        for line in file:
            batch.append(line.rstrip("\n"))
            if len(batch) == batch_size:
                yield batch
                batch = []
    if batch:
        yield batch

这段代码第一次看容易懵，先把几个名词掰开：

  • 可迭代对象（iterable）：实现了 __iter__ 的对象，比如 list、dict、文件对象。它的本事是“能给你一个遍历用的东西”，for 循环开头隐式调用的就是它。
  • 迭代器（iterator）：实现了 __next__ 的对象，内部记着“遍历到哪了”。每次要下一个元素就调一次 __next__，遍历完了就抛 StopIteration。for 循环就是不停地向它要元素，直到收到 StopIteration 才结束。
  • 两者的关系：for x in obj 实际执行的是 it = iter(obj)（调 obj.__iter__() 拿到迭代器），然后反复 next(it)。所以“可迭代”是门票，“迭代器”才是真正在走的那只指针。
  • 生成器（generator）：函数体里只要出现 yield，这个函数就变成了“生成器函数”——调用它不会执行函数体，只会返回一个生成器对象（它同时是迭代器）。函数体要等到你第一次 next() 它才开始跑，跑到 yield 处交出一个值，然后整个函数暂停在那，下次 next() 从暂停处继续。

对照这个流程读 read_batches：

  • 调用 read_batches("data.txt", 2) 此刻什么都不执行，只拿到一个生成器；
  • 第一次要数据时，函数开始跑：读文件、往 batch 里攒行，攒够 2 行执行到 yield batch，把这一批交出去并暂停；
  • 下次要数据时，从暂停处继续：batch = [] 清空，接着攒下一批；
  • 文件读完、循环退出，末尾的 if batch: yield batch 负责把不满一批的剩余行也交出去（比如 5 行、batch_size 2，会产出 2、2、1 三批）；
  • 函数跑到底自动抛 StopIteration，消费方的 for 循环随之结束。

用起来是这样的：

for batch in read_batches("data.txt", 2):
    process(batch)   # 每次拿到 2 行，内存里始终只有这一个批次

yield 返回一个值后暂停函数，下一次迭代从暂停位置继续。与一次性构造完整列表相比，生成器的峰值内存通常只与一个批次相关，适合流式数据管线——如果上面这个例子改成先 return [所有行] 再切片，1 GB 的日志文件就要先在内存里铺满 1 GB；用生成器，内存里永远只有当前那一批。

需要记住

  • 生成器通常只能消费一次。迭代器的状态只会往前走，走完就没了，没有“回头”这个操作。for 过一遍之后再 for 第二遍，第二遍什么也拿不到；想重来只能重新调用一次生成器函数，造一个新的。列表则随便遍历多少遍，这是两者本质的不同。

  • 惰性求值会把异常推迟到迭代时。因为函数体在第一次 next() 之前根本没执行，所以“文件不存在”这类错误不会在调用 read_batches(...) 那一行爆出来，而是爆在开始迭代的地方。写代码时别假设“调用成功 = 没问题”，错误可能藏在后面的迭代里。

  • 把生成器转成 list 会重新物化所有元素，失去节省内存的优势。list(read_batches(...)) 等于把流式处理退化回“全部装进内存”，和生成器的设计初衷正好相反。转 list 只在确实需要反复随机访问全部数据时才做。
