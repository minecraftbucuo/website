08 · 内存管理（五）：踩坑实录与本章小结

上一篇：08-4-内核堆。至此三层分配体系全部跑通，本章的代码完结。
本篇把过程中实际踩过的坑收拢成册，再全章回顾一遍。
（×8 大坑在 08-3 的踩坑实录里，此处不重复。）

踩坑实录

坑 1：预测 4000，实际 5000——起点差了一页

给分配器写预测时，最初的推理是"位图放第 0 页，占 1 页不够就 4 页，第一次分配从 0x4000 开始"。实际跑出来是 0x5000。

排查：位图确实占了 4 页没错，但它不在 0x4000，也不在 0x0——回头看清单第一行是 1000 +86000 usable，第一个 usable 区段从 0x1000 开始，位图放在它的开头，占了 0x1000~0x4FFF。

两个知识漏洞叠在一起：

  1. 物理页 0 从一开始就不在 usable 清单里。OVMF（以及多数真实固件）保留 0 地址附近的第一页——空指针的值是 0，把 0 地址当正常内存分出去，空指针解引用会"成功"读出数据、错误被吞掉。保留它，空指针一碰就崩，错误当场暴露
  2. print_hex 不带 0x 前缀。串口打 1000，第一眼很容易读成"一千"，实际是 0x1000 = 4096。读自己内核的日志要时刻带着这个意识

教训：分配器的世界从清单第一段 usable 开始，不是从 0 开始；预测数字要严格从清单推，不能凭直觉。

坑 2：数字每天不一样，以为代码坏了

隔天重新 make run，usable total、frame allocator up 的数字和上一天对不上（比如 free 从 1CD67 变成 1CD0E）——第一反应是"代码被我改坏了"。

排查：逐区段重新对账，发现清单本身变了。OVMF 每次开机自己分配的内存略有不同，它分多少、哪些区段标 usable 就跟着微变。代码没有任何问题。

教训：判断分配器对错的标准是"账平"，不是"数字固定"。每次开机都验一遍等式：

空闲页数 = usable 区段的页数总和 − 位图自占页数（4 页）

等式平 = 对。数字本身每天可以不同。

坑 3：6 个 never used 警告出现又消失

heap.rs 刚建好、还没接线时，cargo build 一次冒出 6 个警告：START/SIZE/TOP/init/alloc/dealloc ... is never used。这是中间态的正常现象——文件写了，还没人调用它。

选择是不加 #[allow(dead_code)] 压制，让警告留着。等 #[global_allocator] 接上、heap::init 在 main.rs 里被调用后，6 个警告一个不剩全部消失——每个函数都找到了它的调用者。

教训：接线前的死代码警告可以容忍，接线后还在才是问题。警告在这里反而起了清单作用：它精确列出了"还没被用到的函数"，接一条消一个，全消 = 接线完整。

本章小结

三层分配体系，从下到上：

层文件职责关键数字
拿清单boot.rs两张 Limine 需求单：内存清单 + HHDM 偏移清单 32 行，usable 共 0x1CD12 页
页帧分配mm.rs位图记账，只发整页 4KB4 页位图管 0x1DF95 页（12.2 万页）
内核堆heap.rsbump 分配，任意字节数；GlobalAlloc 接入 Box/Vec1080 页 ≈ 4.2MB

一条完整的分配链，以 Box::new 为例：

Box::new(x)
  → GlobalAlloc::alloc(Layout)          #[global_allocator] 指到 KernelHeap
  → heap::alloc(8, 8)                   bump：对齐、检查、游标前移
  → （建堆时已通过 mm::alloc_frame 领好页）
  → 返回堆内虚拟地址（HHDM：物理 + 偏移）

本章沉淀的两个方法论，比代码本身更值钱：

  1. 预测先行：跑实验前先把期望数字从机制一步步推出来写在纸上——预测与输出不符的瞬间就是 bug 暴露的瞬间（×8 大坑、坑 1 都是这么抓到的）
  2. 当场对账：分配器的每个数字都有出处（清单、位图自占、页数换算），账平即正确，账不平必有单一原因可查

遗留清单（后面章节的伏笔）

  • bump 堆不回收：堆用满即终。等内核需要长期运行、频繁分配时，换成能回收的分配器（链表法/伙伴系统）
  • count_free 全位图扫描：每次统计都数 12 万页，页多了会慢——统计应该 O(1) 维护计数器，留作优化
  • Shared 模式第三次重复：serial、console、mm 各抄了一份 UnsafeCell + 手写 Sync 的包装，第 09 章抽成公共模块
  • panic_handler 还是死循环：现在有堆了，可以升级成"打印 panic 位置后停机"
